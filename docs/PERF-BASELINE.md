# 性能基线

记录各阶段耗时的实测值，供回归比较。与 `docs/ORACLE-DIFF.md` 一样：留证据，而不是只报"变慢了"。

## 怎么跑

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
powershell -ExecutionPolicy Bypass -File scripts\perf-baseline.ps1 -Scales 10,50,100,251
```

脚本按文件数从官方语料切子集（复制到 `build/perf-corpus-<n>/`），逐档跑 `-Check` 并记录：
加载（含标准库）、语义校验、以及整轮 wall time。报告落在 `build/perf-*.json`。

环境：Windows，JDK 21（Android Studio JBR），OMG Pilot 0.57.0-SNAPSHOT（本地构建产物），
语料 = `SysML-v2-Release/sysml/src`（共 251 个 `.sysml`）。

## 观察

**一、固定成本约 8 秒。** `samples/` 只有 14 个文件，加载也要 8.0 秒——那是 JVM 启动 +
标准库加载 + 工作区解析的固定开销。比较不同规模的数据时要先把它减掉。

**二、解析与链接约 1 秒/文件，是绝对大头。** 减掉固定成本后：10 文件 12.8s、
50 文件 53.8s、100 文件 156.4s、251 文件 233.9s。这部分**不是我们的代码**，是官方
Xtext 解析 + 全量链接（`resolveAllInputResources`）的代价。要提速只能走增量加载或缓存，
那是独立议题。

**三、我们自己的阶段很便宜。** 语义校验 251 文件只要 8.8 秒（约 35 ms/文件）；
`samples/` 14 文件 0.2 秒。也就是说**在优化之前，先确认瓶颈在谁身上**——目前看不在我们这边。

**四、官方语料全量零错误。** 251 个文件里 0 个有错误、11 条警告；100 文件子集 5 条警告。
警告内容与分布待归类（下一步补进本文件）。

# 性能基线

记录各阶段耗时的实测值，供回归比较。与 `docs/ORACLE-DIFF.md` 一样：留证据，而不是只报"变慢了"。

## 怎么跑

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
powershell -ExecutionPolicy Bypass -File scripts\perf-baseline.ps1 -Scales 10,50,100,251
```

脚本按文件数从官方语料切子集（复制到 `build/perf-corpus-<n>/`），逐档跑 `-Check` 并记录：
加载（含标准库）、语义校验、**索引构建**、**追溯矩阵**，以及整轮 wall time。
报告落在 `build/perf-*.json`。

> 跑批前先告知使用者并把驱动进程降到 `BelowNormal`——一轮全量约 55–65 分钟、
> 单进程常驻 700MB–1GB（实测记录见 `AGENTS.md`）。

## 2026-09-13 首次基线

环境：Windows，JDK 21（Android Studio JBR），OMG Pilot 0.57.0-SNAPSHOT（本地构建产物），
语料 = `SysML-v2-Release/sysml/src`（共 251 个 `.sysml`）。

| 14（`samples/` 自建样例） | 8.0 | 0.2 | 9.8 | 0 | 0 |
| 10（语料子集） | 20.8 | 1.0 | 23.0 | 0 | 0 |
| 50 | 61.8 | 2.6 | 65.6 | 0 | 0 |
| 100 | 164.4 | 5.3 | 170.9 | 0 | 5 |

## 观察

**一、固定成本约 8 秒。** `samples/` 只有 14 个文件，加载也要 8.0 秒——那是 JVM 启动 +
标准库加载 + 工作区解析的固定开销。比较不同规模的数据时要先把它减掉。

**二、解析与链接约 1 秒/文件，是绝对大头。** 减掉固定成本后：10 文件 12.8s、
50 文件 53.8s、100 文件 156.4s、251 文件 233.9s。这部分**不是我们的代码**，是官方
Xtext 解析 + 全量链接（`resolveAllInputResources`）的代价。要提速只能走增量加载或缓存，
那是独立议题。

**三、我们自己的阶段很便宜。** 语义校验 251 文件只要 8.8 秒（约 35 ms/文件）；
`samples/` 14 文件 0.2 秒。也就是说**在优化之前，先确认瓶颈在谁身上**——目前看不在我们这边。

**四、官方语料全量零错误。** 251 个文件里 0 个有错误、11 条警告；100 文件子集 5 条警告。
警告内容与分布待归类（下一步补进本文件）。

## 2026-09-14 复测（阶段 3 新增：索引与矩阵）

环境同首版；这批在 `BelowNormal` 优先级下跑（用户实测风扇噪音后定的约定，见 `AGENTS.md`），
所以绝对值会比首版略高——**同一批数据内部横向比较才有意义**。

| 文件数 | 加载 (s) | 校验 (s) | 索引 (s) | 矩阵 (s) | wall (s) | 错误 | 警告 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 10 | 23.0 | 1.1 | 27.3 | 25.7 | 26.1 | 0 | 0 |
| 50 | 69.8 | 3.0 | 78.0 | 74.4 | 74.7 | 0 | 0 |
| 100 | 164.9 | 5.2 | 178.7 | 175.9 | 172.0 | 0 | 5 |
| 251（`sysml/src` 全量） | 232.0 | 8.7 | 255.5 | 251.9 | 242.7 | 0 | 11 |

> 这一档报告里是 `files=250`：脚本切子集时把文件摊平复制，语料里同名不同目录的文件
> 互相覆盖少了一个（已修：现在保留相对目录结构）。真实 251 文件的加载/校验见 T1
> （load 242.3s、check 9.2s），与这次的 232.0 / 8.7s 在噪声范围内一致。

**新增两段的净成本（wall − load）**：

| 文件数 | 索引构建 | 追溯矩阵 |
|---:|---:|---:|
| 10 | +4.3s | +2.7s |
| 50 | +8.2s | +4.6s |
| 100 | +13.8s | +11.0s |
| 251 | +23.5s | +19.9s |

结论：**索引与矩阵都不是瓶颈**——两段合起来仍是加载成本的零头，量级与语义校验相当
（几十毫秒/文件：251 文件档分别是 94ms/文件与 79ms/文件）。阶段 3 新增的能力在性能上
基本是"免费"的。

## 阈值策略

第一次跑出基线后，以 **基线 × 1.5** 作为回归线；超出需要在提交信息或本文件里解释原因。
不预先编造阈值——没有数据支撑的数字只会变成噪声。
